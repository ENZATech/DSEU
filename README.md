# CampusDesk App

CampusDesk is an Android campus-management app backed by a Python REST API and SQLite. The Android project is in `android/`; the API is in `backend/`.

## Download the Android APK

The APK build is configured to use the live HTTPS API URL at build time.

1. Deploy the backend using the `render.yaml` Blueprint (see [Deploy the backend](#deploy-the-backend)).
2. The workflow uses `https://campusdesk-api-j6os.onrender.com` by default. To use a different backend, add `CAMPUSDESK_API_BASE_URL` under **Settings → Secrets and variables → Actions → Variables** with the backend's HTTPS base URL (without a trailing slash).
3. Open **Actions → Build CampusConnect APK → Run workflow**.
4. Open the completed workflow run and download the `CampusConnect-debug-apk` artifact. Extract `app-debug.apk`, then install it on an Android device. If Android blocks installation, allow installation from your browser or file manager.

This is a debug APK for testing, not a signed Play Store release. The workflow requires a valid HTTPS backend URL and defaults to the CampusDesk API listed above.

## Deploy the backend

1. In Render, create a new **Blueprint** from this GitHub repository and approve the settings in `render.yaml`.
2. The Blueprint creates a Docker web service and a 1 GB persistent disk mounted at `/var/data`. Persistent disks require a paid Render service; check Render's current pricing before creating it.
3. `CAMPUSDESK_ADMIN_PASSWORD` is generated by Render. Retrieve it from the service's environment settings and sign in with username `campusadmin`. Store it securely; changing this environment variable later does not update an existing admin password in the database.
4. Confirm the service's `/health` endpoint returns `{"ok":true,"service":"CampusConnect API"}`.
5. Add its HTTPS base URL as the GitHub Actions variable above, then run the APK workflow.

The hosted backend does not seed sample students or faculty. Create students through the app after signing in as the admin. For local development only, sample records are seeded by default.

## Run locally

Requires Python 3.10+; the API uses only the Python standard library.

```powershell
cd backend
$env:CAMPUSDESK_ADMIN_PASSWORD = "choose-a-unique-local-password"
python server.py
```

The API listens on `http://127.0.0.1:8000`; test `http://127.0.0.1:8000/health`. Local demo accounts are created only in a fresh local database:

- Admin: `campusadmin` / `Campus@2026` (override with `CAMPUSDESK_ADMIN_PASSWORD`)
- Student: `student105` / `student123`
- Students `student106` and `student107` also use `student123`

Never use these sample credentials or sample data on a public deployment. To start locally without demo student/faculty records, set `CAMPUSDESK_SEED_DEMO_USERS=false` before the first run.

Open the `android` folder in Android Studio to build/run locally. The APK defaults to the live HTTPS API; to use a local backend, set the API address in the app's **Server settings** to `http://10.0.2.2:8000` for the Android emulator or your computer's LAN address for a physical phone.

## API endpoints

- `GET /health` — health check
- `POST /api/login` — returns a bearer token
- `GET /api/me` — current signed-in user
- `GET /api/leaderboard` — student leaderboard
- `GET /api/student/progress` — signed-in student's progress
- `GET /api/students` — admin-only student directory
- `POST /api/students` — admin-only create student
- `PATCH /api/students/{roll_no}/cgpa` — admin-only CGPA update
- `GET /api/faculty` — admin-only faculty directory
- `POST /api/faculty` — admin-only add faculty

## Security and persistence

- The Render configuration uses HTTPS at the service edge, a generated initial admin password, no demo student records, and a persistent SQLite disk.
- API bearer tokens are kept in memory and expire after seven days; a service restart invalidates active sessions.
- This starter app has no login rate limiting and is not security-audited. Do not store real student records or use this for a production college system without a security review and operational safeguards.
